# Manual test session — 2026-11-22 (mock data, phone)

A hands-on manual test of BookRough **on production** (`https://bookrough.vercel.app`), mainly on the developer's iPhone, after the mock data set was injected (docs/manual-tests/mock-data/README.md). Claude guides it, and the developer clicks through and reports what they see. **Nothing is fixed during the session.** Findings are recorded here and turned into fix sessions afterwards, if the developer wants them.

This file began as a working log in the repo root. The developer chose to commit it here on 2026-11-24. Follow-up: F1, D3 and D4 were fixed in PR #91; the parked ideas D1 (PR #94), D2, D5 and the later D6 (in-app player) were built afterwards, each in its own session — see DEVELOPMENT.md. The mock data is still in production until `remove.sql` runs before launch (docs/manual-tests/mock-data/README.md §6).

---

## 1. Goal

- See how the app looks and behaves with a realistic amount of data: long feeds, many notifications, threads, many friends and communities.
- Check this on the phone first (Safari and the installed PWA), then on desktop where it helps.
- Find bugs, UX problems and design problems, and collect the developer's notes.

## 2. Method

1. **One test per message.** Claude says what to open or click and what should appear.
2. The developer replies:
   - **"תקין"**: passed. Move on.
   - **"דלג"**: skipped. Recorded with the reason, if one was given.
   - **Anything else** is a finding. Claude asks at most one clarifying question, records it, and moves on.
3. Claude updates this file after every test: the result in §5, findings in §6, notes in §7.
4. Severity for findings: **bug** (something is wrong or broken), **UX** (it works but is confusing or awkward), **design** (looks or layout).
5. Claude runs every command (CLAUDE.md §11). The developer never types a command.

## 6. Findings

| #   | Test | Severity | Finding                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

| F1  | 12   | design   | **Hebrew text with trailing punctuation renders in the wrong direction.** The description "הקלאסיקות של פעם, בלי פשרות." shows its period at the **left** end, before the first word (screenshot, iPhone Safari). Cause: user-written text is laid out left-to-right (the page is LTR, English-only UI), so a neutral character at the end of a Hebrew sentence takes the paragraph's LTR direction. Likely fix: `dir="auto"` on elements that show user-written text (descriptions, comments, reviews, names, song titles), which sets each one's direction from its own first strong character. Note for the fix session: CLAUDE.md §8 forbids "`dir` switching" for the UI; this is about the direction of user content inside an English UI, so it needs the developer's confirmation that §8 allows it (and a line added there) |
