### 1. Authentication & Onboarding Flow

Google Sign-In is the only authentication method, so this group collapsed from five screens to two. Sign-up and login are two choices, "Sign in" and "Create account", above one Google button (`docs/features/sign-in-sign-up.md`).

- **1.1. Welcome / Landing Screen (UC-1, UC-2)**
  - **Purpose:** The single entry point for unauthenticated users. Handles both registration and login.
  - **Key UI:** App logo, brief value proposition, a "Sign in" / "Create account" switch (Sign in first), and one Google button whose words follow it ("Sign in with Google" / "Sign up with Google"). Sign in with no account shows "No account for this Google account yet." with "Create account" and "Use another Google account". Below it, a short line of copy setting expectations: that the app never asks for a password and never stores an email address.
  - **States:** idle; signing-in (button disabled with spinner while the popup is open and the token is being verified); error ("Sign-in failed. Please try again.").
  - **Install hint:** on an iPhone or iPad browser — not in apps' in-app browsers, never inside the installed app — a dismissible bar at the top: "Install BookRough: tap Share (in Safari it's under •••), then Add to Home Screen." A dismissal is remembered on the device (`docs/features/pwa-installable.md` §5.1).
  - **No** "Log In" / "Sign Up" split, **no** email or password fields, **no** "Forgot Password?" link.
- **1.2. Complete Your Profile Screen (UC-1)**
  - **Purpose:** Collect the fields Google cannot supply. Shown immediately after a first successful sign-in, and again on any later sign-in where onboarding was abandoned.
  - **Key UI:** Display Name input with live availability feedback (any language, must be unique), an avatar choice between the **generated avatar** (default, live preview) and the user's Google photo when one exists (no upload control), and a mandatory selector for **Preferred Streaming Service** with nothing pre-selected.
  - **States:** loading; validation error ("That display name is already taken."); submitting.
  - The dashboard is unreachable until this screen is completed.

> **Removed screens.** The former Registration (1.2), Login (1.3), Forgot Password (1.4), and Create New Password (1.5) screens have all been **withdrawn**. There are no passwords to enter or reset and no email address to send a link to - see `docs/auth.md` section 1.1 and the withdrawn UC-17. The catalog is now **seventeen** screens (thirteen after the withdrawal, plus Join Community / Invite Preview, added with UC-15 in Phase 2, the Admin screen, added with UC-19, Recommendations, added with UC-20, and Notifications, added with UC-21). (It previously held sixteen; the "thirteen" figure quoted in earlier drafts of CLAUDE.md never matched the actual list and has been corrected.)

> **Administrative screens (UC-19)** are in group 5 below, specified in `docs/features/admin-panel.md`. They are reachable only for `users.role = 'ADMIN'`, they render the standard not-found page for everyone else, and **they cannot display an email address because none is stored.**

### 2. Main Navigation & Social Flows

These screens represent the core social and discovery aspects of the app.
- **2.1. Communities Dashboard (Home Screen)**
  - **Purpose:** The central hub displaying all the groups a user belongs to.
  - **Key UI:** List of joined Communities as cassette cards (the community's own stripe colour, name, member count and your role), newest joined first, ending in a dashed "Create community" tile. The header carries the BookRough logo, a Search icon that opens Global Search (2.2) and a bell with the unread count (2.6); a "Sign out" button sits beside the "Your communities" heading and asks "Sign out?" first (UC-3). The Home tab carries the same unread count. A bottom tab bar switches between Home, Friends, Share, My List, and Profile: Friends is 2.3 (with a badge counting pending friend requests and community invitations, "9+" above nine), Share is a raised button in the centre that opens the Share sheet (below), My List is 4.1, and Profile is My Profile / Settings (4.3). Search has no tab. The look is the "Mixtape" design, `docs/features/ui-redesign.md`.
  - **Share sheet:** the centre Share button opens a sheet titled "Share a song" with two choices. "To a friend" opens the direct-recommendation sheet with its friend picker (2.5). "To a community" lists your communities (skeleton rows, an error with Try again, or "Create community" when you have none); choosing one shows that community's composer (3.1) inside the sheet, and a successful post closes it and opens the community's feed with the post on top. A community that is gone sends the sheet back to the list, reloaded. The back arrow returns one step. Posting from the feed itself still works (`docs/features/ui-redesign.md` §5.0b).
  - **States:** skeleton cards while loading; an empty state ("Start your first community") with a single Create button; an inline error with Try again.
- **2.2. Global Search Screen (UC-5)**
  - **Purpose:** Finding other users on the platform.
  - **Key UI:** Reached from the Search icon in the Home and Friends headers (Search has no tab): a field that searches as you type (the query is kept in the URL, so Back restores it) and a list of results — avatar and display name, "You" on your own row — each opening the Public User Profile (yours opens My Profile). Beside every other result, the friend control: "Add Friend", "Request sent" (Cancel request in a sheet), "Respond" (Accept / Ignore in a sheet), or a quiet "✓ Friends" label — removing a friend stays on the profile (`docs/features/search-friend-button.md`). Matching ignores case and accents, names starting with the query first, at most 20 with "Showing the first 20. Type more of the name to narrow it down." States: a hint before typing ("Find friends by their display name."); skeleton rows; UC-5's empty state; "Couldn't search right now." with Try again; offline banner with the field disabled (`docs/features/find-people.md` §5.1).
- **2.3. Friends & Requests Screen (UC-7, UC-8)**
  - **Purpose:** Managing bidirectional social connections.
  - **Key UI:** The Friends tab (/friends), with the Search icon in its header. A "Recommendations" row at the top opens 2.5, with the count of new ones. "Invitations" to communities first, newest first, each with the community's small cover, name, "{inviter} invited you · {n} members", "Join" (opens the community, toast "You joined {name}.") and "Decline" (`docs/features/invite-friends.md` §5.4); then "Requests", newest first, each with the sender's name (linking to their profile), when it was sent, "Accept" and "Ignore"; then "Your friends", alphabetical, each linking to their profile, with a ⋯ that opens "Remove friend?" ("Remove {name} from your friends? They won't be notified.", Remove friend / Cancel; UC-8, `docs/features/unfriend.md`). Accept toasts "You're now friends with {name}."; a request that is gone toasts the server's message and leaves the list. States: skeletons; "No friends yet" with a link to Search; "Couldn't load your friends." with Try again; offline banner with Accept and Ignore disabled (`docs/features/friend-requests.md` §5.2).
- **2.4. Public User Profile Screen (UC-5, UC-6)**
  - **Purpose:** Viewing another user's details and initiating connections.
  - **Key UI:** At /users/:id. The person's avatar, display name and "Listens on {service}"; their ratings in communities you share, newest first with Load more, each showing the song (or "Shared from {service}"), the score, the comment, the community and the time, and opening Post Detail. The same profile opens from any name on a post card, a Post Detail rating or a Community Settings member row; your own id opens My Profile. Under the header, "Send a song" for a friend (2.5), and the friend control: "Add Friend"; "Request sent" (a sheet with "Cancel request"); "Respond" (a sheet with "Accept" and "Ignore"); or a "Friends" button that opens the same "Remove friend?" sheet (`docs/features/friend-requests.md` §5.3). States: skeletons; "No ratings to show" for someone you share no community with; the ratings fail separately ("Couldn't load ratings." with Try again) while the header stays; an unknown user shows the not-found page (`docs/features/find-people.md` §5.2).
- **2.5. Recommendations Screen (UC-20)**
  - **Purpose:** Sending a song to one friend, and finding what friends sent you, with no community in common.
  - **Key UI:** At /recommendations, from a row at the top of Friends. "Send a song" and a Received / Sent switch, Received first; opening Received clears the Recommendations row's count. Cards are the feed's, with "From {name}" or "To {name}". On Received: "Rate & Review" (the rating sheet, 4.2; "You're no longer friends with {name}" instead after unfriending), the bookmark, and a ⋯ with "Hide", confirmed with "Hide this from Received? {name} won't be told." On Sent: the rating, "Find on other services" when pending, and a ⋯ that deletes for both. "Send a song" opens one sheet: a friend picker (from a profile the friend is already chosen), the link, an optional comment (n/280), and "Send", with the same busy copy as posting; the sheet cannot be dismissed while converting, and only success clears the draft.
  - **States:** card skeletons per list; "Nothing here yet" and "You haven't sent anything"; "Couldn't load your recommendations." with Try again; Load more; "Add a friend first" with a link to Search; refusals and failures inline in the sheet; offline banner with every write disabled, loaded lists readable, nothing queued (docs/features/direct-recommendations.md §5).

- **2.6. Notifications Screen (UC-21)**
  - **Purpose:** Seeing what concerns the user: new posts in their communities, direct recommendations, ratings of their posts, friend requests and acceptances, and community invitations.
  - **Key UI:** At /notifications, from the bell in the Home header. Newest first; each row shows the actor's avatar, one line ("Dana posted in Friday Jazz", "3 new posts in Friday Jazz · latest from Dana", "Noam rated Blue 8/10") and a relative time, unread rows tinted and dotted. Tapping a row marks it read and opens it: the feed, Recommendations, the post, Friends, or the friend's profile. "Mark all as read" in the header; "Load more" pages.
  - **States:** skeleton rows while loading; an empty state ("No notifications yet"); an inline error with Try again; offline, the last loaded list, with "Mark all as read" disabled and a note.

### 3. Community & Core Music Flow

These are the most heavily trafficked screens where the primary value exchange happens.
- **3.1. Community Feed (UC-11, UC-12, UC-18)**
  - **Purpose:** The main timeline for a specific group, displaying all music recommendations.
  - **Key UI:** * Header with Community Name and settings icon.
    - Input area, collapsed to a "Share a song or album" pill until tapped (✕ collapses it again and keeps the draft): URL paste box and optional comment (counter n/280) with Post. While the link converts, the button reads "Finding this track on other services…" ("Getting the details…" for a Bandcamp or SoundCloud link) and the fields are read-only; an invalid link shows the UC-11 message under the field with the draft kept.
    - Feed of Post Cards, newest first with Load more: the author and time, cover art, title, artist, an "Album" label for albums, the comment, an "Open in {your service}" button (the original link when your service has no match) and "Other services" (a sheet of every link). A post saved during an outage reads "Shared from {service}" with "Other services unavailable", and its author sees "Find on other services". On other people's posts, a bookmark icon saves to Listen Later: outline or filled, with "Added to Listen Later" / "Removed from Listen Later" toasts, disabled offline (UC-12, `docs/features/bookmarks-my-list.md`). Once the viewer has rated a post, the bookmark is replaced by "You rated {n}/10" (`docs/features/rate-post.md`). Under the song, "★ {average} · {n} ratings" once someone has rated, then "· {n} comments" once anyone has commented (UC-22), and a "View ratings" link to Post Detail (the title links there too; UC-16).
    - A link-only post — Bandcamp, SoundCloud, or a YouTube video squigly finds on no other service — has one button for every viewer, "Listen on Bandcamp", "Listen on SoundCloud" or "Watch on YouTube", a "Set" or "Video" label where it applies, and no Other services or Find on other services; without metadata its title reads the platform's name. The same card appears in Recommendations, My List, Post Detail and on profiles (`docs/features/link-only-posts.md` §5).
    - A ⋯ "Post options" menu on posts you may delete — your own, or any post if you are an Admin or the Owner — expanding to "Delete post". The confirmation uses UC-18's wording for your own post and "Delete [Author]'s recommendation? … [Author] won't be notified." for someone else's; success toasts "Post deleted" and the card leaves the feed (UC-18, `docs/features/posts-delete.md`). Your own post's menu also offers "Edit comment" above it: a sheet with the comment, n/280, Cancel and Save, toast "Comment updated"; an edited comment shows "· edited" beside the time (`docs/features/edit-post-comment.md`).
    - States: post skeletons while loading; "Share the first song" when empty; "Couldn't load posts." with Try again; offline banner "You're offline. Connect to post." with posting disabled while the feed stays readable. Detail: `docs/features/posts-feed.md` §5.
- **3.2. Create Community Screen (UC-9)**
  - **Purpose:** Setting up a new group.
  - **Key UI:** A full-screen form (not a modal, so the phone's back gesture works) for Community Name and Description, with a live preview of the generated cover graphic (neutral until the community exists, since its colour comes from the id; no upload control). "Invite friends": the creator's friends, each with a checkbox; the ticked ones are invited once the community exists, and a failure still lands on the community with "Your community is ready, but the invitations weren't sent. Try again from Invite friends." (`docs/features/invite-friends.md` §5.2).
  - **States:** required-name error ("A Community name is required."); submitting ("Creating…"); offline banner. On success the user lands on the community's page, which shows the cover, name, description, member line, and a "Posts are coming soon" panel until Phase 3. A community the user is not in renders the standard not-found page.
- **3.3. Community Settings & Members Screen (UC-10, UC-14, UC-15)**
  - **Purpose:** Managing the group's roster and individual participation.
  - **Key UI:** Opened from a "Settings" button on the community page. Everyone: the member list (avatar, name, "You", an "Owner" / "Admin" label) and "Leave community" with a confirmation — the Owner instead sees the transfer-or-delete message. Admins: editable name and description with "Save changes"; the invite panel (also on the community page, and opening once by itself after a community is created) — "Friends" first, each friend marked Member, Blocked, Invited (tap to cancel) or with "Invite", then the invite link; a ⋯ menu on rows they may act on — "Make admin", "Make member", "Remove from community" (confirmation; removal also blocks and deletes their posts and ratings here); and a "Blocked" list with "Unblock". The Owner additionally: "Make owner" (confirmation) and "Delete community", confirmed with a warning and an "I understand this can't be undone" checkbox.
  - **States:** loading skeleton; load error with Try again; not a member → the standard not-found page; actions in progress keep their sheet open; offline banner disables every action while the list stays readable.
- **3.4. Post Detail / Feedback Screen (UC-16)**
  - **Purpose:** Viewing the detailed discussion and ratings for a specific recommendation.
  - **Key UI:** At /posts/:id. A back link to the community, or to Recommendations on a direct recommendation (2.5); the song card as in the feed (its ⋯ menu edits your comment, or deletes the post and returns to the community); a large average ("7.5 out of 10 · 4 ratings", or "No ratings yet"); and every member's rating, newest first: avatar, name ("You" for yours), score n/10, comment and time. Your own rating has "Edit" (on a direct recommendation, only while you are friends), which opens the rating sheet pre-filled ("Edit your rating", "Save changes", toast "Rating updated"). States: skeletons; a post you cannot see shows the not-found page; "Could not load comments at this time." with Try again while the card stays; offline disables Edit (`docs/features/post-detail.md`). Under each review, its thread of replies, with "Reply"; below the ratings, "Discussion" (UC-22): an "Add a comment" box (n/500, Send), then the post comments, each with its own thread. A reply to someone other than the thread's opener is labelled "↩ to Dana"; Reply opens an inline box, "Replying to Dana · Cancel". Your comments have a ⋯ menu with Edit (inline, marked "· edited") and Delete ("Delete this comment?"); admins and the owner delete any. A deleted comment with replies reads "Comment deleted". States: a skeleton; "No comments yet. Start the conversation."; "Couldn't load the discussion." with Try again; offline, Send and Reply disabled with "You're offline. Connect to comment."; after unfriending, a direct item's discussion is read-only with "You're no longer friends with {name}" (`docs/features/discussion-threads.md` §5).
- **3.5. Join Community / Invite Preview (UC-15)**
  - **Purpose:** What a friend sees when they open an invite link — signed in or not, with an account or not.
  - **Key UI:** The community's generated cover, name and member count under "You're invited to". Signed out: the Sign in / Create account switch (Create account first) and the Google button, under "Sign in or create an account to join"; a new user completes their profile and returns here. Signed in: a "Join community" button, or "You're already in this community." with an Open link.
  - **States:** loading skeleton; joining ("Joining…"); invalid or reset link (the UC-15 message, with a link home); other load failure (Try again); offline (Join disabled).

### 4. Personal Management Flows

Screens dedicated to individual user actions and backlog management.
- **4.1. "My List" / Listen Later Screen (UC-12, UC-13)**
  - **Purpose:** The user's personal queue of bookmarked, unrated songs.
  - **Key UI:** List of saved song cards, newest saved first: cover, title, artist, "Shared by {author} in {community}", or "Sent by {sender}" for a direct recommendation (the community links to its page while you are a member; songs from a community you left stay) and when it was saved. "Open in {your service}" opens it in their preferred music app, falling back to the original link; "Remove" takes it off the list at once. Each card has a prominent "Rate & Review" button that opens the rating sheet (4.2); for a community the user is no longer in, the line "You're no longer in {community}" replaces it, and for a former friend's direct recommendation, "You're no longer friends with {name}". States: card skeletons; "Nothing saved yet"; "Couldn't load your list." with Try again; Load more; offline banner with Remove and Rate & Review disabled (`docs/features/bookmarks-my-list.md`).
- **4.2. Submit Rating Modal / Screen (UC-13)**
  - **Purpose:** The interface for leaving feedback on a listened-to track.
  - **Key UI:** A sheet titled "Rate & Review" with the song, a row of ten stars for the score 1-10 with an "N/10" readout ("Your score"; tap, drag across the row, or use the arrow keys), an optional comment with a counter (n/280), and a "Submit Rating" button, disabled until a score is chosen. Submitting shows "Submitting…"; success toasts "Rating submitted" and the song leaves My List; a deleted post leaves with UC-13's message, a second rating with "You already rated this post."; validation and network errors stay inline with the draft kept; offline disables Submit (`docs/features/rate-post.md` §5.2).
- **4.3. My Profile / Settings Screen (UC-3, UC-4)**
  - **Purpose:** Managing personal account details and app preferences.
  - **Key UI:** The fields are editable in place: the avatar, Display Name (with the same live availability check as onboarding) and Preferred Streaming Service. One "Save changes" button, enabled only once something changed, sends only the changed fields and toasts "Profile updated". A "Sign out" button at the bottom, which asks "Sign out?" first, like the one on Home.
  - **Avatar:** "Upload a photo" in every state — the browser crops a centre square and shrinks it, the server re-encodes it; "Uploading…", then "Photo updated" (`docs/features/avatar-upload.md` §5.1). With a photo in use (Google or uploaded), "Use generated avatar" (the photo is deleted). With the generated avatar, a Google button fetches the current photo through a fresh Google sign-in from the same account; a different account or an account with no photo shows an inline message.
  - **States:** a name problem shows on the name's status line, other save failures inline above Save; offline shows a banner and disables Save and the avatar actions, and the "Sign out?" confirmation is disabled with "You're offline. Connect to sign out."

### 5. Administration (UC-19)

Reachable only by an onboarded user whose `users.role` is `ADMIN` (set in the database). Everyone else - signed-out visitors included - gets the standard not-found page at every `/admin` URL, so the area is never confirmed to exist. Full detail: `docs/features/admin-panel.md`.

- **5.1. Admin Screen (UC-19)**
  - **Purpose:** Let the owner see who uses BookRough and which communities exist, and adjust presentation settings.
  - **Entry:** an "Admin area" link on My Profile, shown only to admins.
  - **Key UI:** heading "Admin" and tabs, each with its own URL:
    - **Users** (`/admin/users`): a count, then one row per user - avatar, display name (or "Not finished signing up"), an "Admin" badge, service, join date, number of communities. No email exists to show; a Google photo appears only if the user chose it.
    - **Communities** (`/admin/communities`): a count, then one row per community - generated cover, name, member count, created date, owner's display name (or "No owner").
    - **Settings** (`/admin/settings`): an on/off switch and text (up to 140 characters) for the announcement banner; five named accent colours as swatches; the Welcome tagline (up to 80 characters) with "Reset to default". One "Save changes", enabled only once something changed and everything is valid, sends only what changed and toasts "Settings saved"; field problems show under the field, other failures inline; offline disables Save. Below, the last 20 changes, e.g. "Ofri changed the accent colour from Purple to Green", with "Deleted account" for an author whose account is gone.
  - List rows are read-only, except one action: a user row with a photo has "Remove photo", confirmed in a sheet, which returns them to the generated avatar (`docs/features/avatar-upload.md` §5.2). Nothing opens a profile or a community.
  - **How the settings apply** (everywhere, not just here): the app fetches them at start without waiting on them, defaults until then or on failure. The accent colour is applied app-wide by name; the tagline is Welcome's subtitle; the banner is a slim plain-text bar at the top of every tabbed screen for signed-in users, dismissible, and shown again when its text changes. Other users get a change on their next app load.
  - **States:** skeleton rows while loading; "No communities yet."; an inline error with Try again; a `403` (role removed mid-session) turns the area into the not-found page.

### 6. Cross-Cutting UI Conventions

These apply to every screen above and are not restated per screen.

- **Language: English only.** All copy, labels, errors, and empty states are in English. There is no internationalisation layer and no RTL support.
- **Mobile-first.** Every layout is designed at 375px width first and expanded upward with Tailwind's `sm:` / `md:` / `lg:` prefixes. The primary surface is an iPhone running the installed PWA; the desktop browser is secondary. Touch targets are at least 44x44px, with one declared exception: the rating sheet's row of ten stars, about 34x44px each at 375px, which runs edge to edge and can be dragged across (`docs/features/ui-redesign.md` §5.10).
- **One upload: your own photo.** Avatars default to initials over a colour derived deterministically from the entity id; a user may choose their Google photo or upload one on My Profile (`docs/features/avatar-upload.md`). Community covers are always generated, and no other screen has an upload control.
- **Three states, always.** Every screen that waits on the network defines a loading state (skeleton or spinner), an empty state, and an error state. A blank area is not a loading state.
- **The posting flow blocks.** Link conversion takes 3-8 seconds and the submit button blocks for its duration behind a spinner with explanatory copy. This is a designed wait, not an accident.
- **Offline.** Installed as a PWA, previously loaded content stays readable without a connection. Write actions (post, rate, bookmark) show an explicit "you're offline" state rather than failing silently or queueing invisibly. A bar at the top says "You're offline — showing what you last loaded."; a screen never loaded shows "You're offline, and this wasn't loaded before." with Try again; with no remembered session the app opens on "You're offline. Connect to open BookRough." When a new version is waiting, a dismissible bar offers Reload. See `docs/deployment.md` §6.
